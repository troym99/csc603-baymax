# AI Inference Service

This directory contains the Python FastAPI service for Baymax.

The service receives text input from the Express backend and returns a generated response.

**Current status:** Mock inference only. Integration with an actual LLM (Llama 3.1 8B Instruct or an alternative model) will be implemented in a future development stage.

## 1. Project Structure

```text
ai-service/
├── main.py              # FastAPI routes and request validation
├── inference.py         # Mock AI inference logic
├── requirements.txt     # Python dependencies
└── README.md            # Setup and testing instructions
```

## 2. Prerequisites

- **Python:** 3.14 recommended 
- **pip:** Python package manager

> Note: The mock service does not require a GPU, Hugging Face account, or downloaded AI model.

## 3. Environment Setup

### Step 1 — Navigate to the AI service directory

From the project root:

```bash
cd ai-service
```

### Step 2 — Create a virtual environment

```bash
python -m venv .venv
```

### Step 3 — Activate the virtual environment

**Windows (PowerShell):**

```powershell
.\.venv\Scripts\Activate.ps1
```

**Windows (Command Prompt):**

```cmd
.venv\Scripts\activate.bat
```

**macOS / Linux:**

```bash
source .venv/bin/activate
```

After activation, your terminal should display `(.venv)`.

### Step 4 — Install dependencies

```bash
python -m pip install -r requirements.txt
```

The current service requires FastAPI and Uvicorn. No model inference libraries are needed for mock testing.

## 4. Start the FastAPI Server

From the `ai-service/` directory, run:

```bash
python -m uvicorn main:app --reload --port 8000
```

The server should be available at:

```text
http://127.0.0.1:8000
```

The `--reload` option automatically restarts the development server when Python files change. It should only be used during development.

Interactive API documentation is available at:

```text
http://127.0.0.1:8000/docs
```

## 5. API Endpoints

### GET `/health`

Checks whether the FastAPI service is running.

**Request:**

```http
GET http://127.0.0.1:8000/health
```

**Expected response (200 OK):**

```json
{
  "status": "ok",
  "service": "ai-inference"
}
```

This confirms that FastAPI is running, not that a real AI model is loaded.

### POST `/generate`

Accepts a text message and returns a mock inference response.

**Request:**

```http
POST http://127.0.0.1:8000/generate
Content-Type: application/json
```

**Request body:**

```json
{
  "message": "What are common causes of headaches?"
}
```

**Expected response (200 OK):**

```json
{
  "message": "Testing testing, mock response. You asked: What are common causes of headaches?",
  "model": "mock",
  "status": "completed"
}
```

The current response is generated by `inference.py` and does not involve a real language model.


## 6. Testing the API

### FastAPI Swagger UI 

1. Start the FastAPI server.
2. Navigate to `http://127.0.0.1:8000/docs`.
3. Expand `GET /health`, click **Try it out**, then **Execute**.
4. Verify that the response status is `200`.
5. Expand `POST /generate` and click **Try it out**.
6. Enter the following JSON:

```json
{
  "message": "What are common causes of headaches?"
}
```

7. Click **Execute** and verify that the mock response is returned.


### Input Validation

The `/generate` endpoint requires a nonempty string in the `message` field, with a maximum length of 2,000 characters.

Invalid input, such as an empty or missing message, should return HTTP `422`.

## 7. Express Backend Integration

The FastAPI service communicates with our existing Node.js/Express backend.

**Request flow:**

```text
Browser (public/index.html)
       ↓
Express Route (src/routes/inference.js)
       ↓
Node Service (src/services/inference.js)
       ↓
FastAPI (ai-service/main.py)
       ↓
Mock Inference (ai-service/inference.py)
       ↓
Response returned to browser
```

The Express service sends HTTP requests to FastAPI using the configured `AI_SERVICE_URL`.

For local development:

```env
AI_SERVICE_URL=http://127.0.0.1:8000
```

The Express and FastAPI servers must both be running when testing the complete pipeline.

## 8. Current Limitations

- **Mock inference only:** The service does not currently load or call an actual AI model. It is designed for local dev and integration testing.
- **No medical intelligence:** Responses are predefined test outputs.
- **No conversation memory:** Each request is processed independently.
- **No RAG integration:** External medical knowledge retrieval and citations are not yet implemented.
